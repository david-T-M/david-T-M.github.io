¿Qué es programar?

Programar es dar instrucciones a una computadora para que realice tareas. Es como escribir una receta, pero para la máquina.

Conceptos Fundamentales

  • Algoritmo: Serie de pasos ordenados para resolver un problema
  • Programa: Un algoritmo escrito en un lenguaje que la computadora entiende
  • Lenguaje de programación: El "idioma" que usamos para comunicarnos con la máquina
¿Qué es PSeInt?

PSeInt es un pseudo-lenguaje diseñado para aprender a programar. Su syntax se parece al español, lo que facilita la comprensión.

Estructura básica de un algoritmo en PSeInt

  Escribir "Hola, mundo!"

1.1 ¿Qué es un Algoritmo?

Un algoritmo es un conjunto finito de instrucciones o pasos ordenados y bien definidos que permiten resolver un problema o realizar una tarea específica.

Definición Formal

Es una secuencia de operaciones sistemáticas que, partiendo de ciertos datos de entrada, produce un resultado (salida) en un tiempo finito.

Características de un Algoritmo

  • Finito: Debe terminar en algún momento (no puede ejecutarse para siempre)
  • Bien definido: Cada paso debe estar claramente especificado
  • Definido: Si se repite muchas veces con los mismos datos, siempre dará el mismo resultado
  • Tiene entrada: Recibe datos iniciales (puede no tener)
  • Tiene salida: Produce un resultado
  • Efectivo: Cada paso debe ser ejecutable

Ejemplo de Algoritmo Cotidiano

Hacer un sándwich
  1. Tomar el pan
  2. Abrir el pan por la mitad
  3. Colocar el ingrediente (jamón, queso, etc.)
  4. Cerrar el pan
  5. Cortar en diagonal (opcional)
  6. Servir

Ejemplo de Algoritmo en Pseudocódigo

algoritmo_suma.pse 
Algoritmo SumarDosNumeros
  // Entrada: dos números
  Definir a, b, suma Como Entero
  
  Escribir "Ingrese el primer número:"
  Leer a
  Escribir "Ingrese el segundo número:"
  Leer b
  
  // Proceso
  suma <- a + b
  
  // Salida
  Escribir "La suma es: ", suma
FinAlgoritmo

Partes de un Algoritmo

Entrada (Input)

Datos que recibe el algoritmo para trabajar. Ejemplo: números que ingresa el usuario.

Proceso

Operaciones que se realizan con los datos. Ejemplo: sumar dos números.

Salida (Output)

Resultado que produce el algoritmo. Ejemplo: la suma de los números.

Almacenamiento

Guardar datos para usarlos después. Ejemplo: guardar la suma en una variable.

1.2 ¿Qué es un Programa?

Un programa es un conjunto de instrucciones escritas en un lenguaje de programación que le indica a la computadora qué hacer. Es la implementación concreta de un algoritmo.

Relación Algoritmo → Programa

Algoritmo: La idea general (receta escrita en español)

Programa: La implementación específica (receta escrita en un lenguaje que la máquina entiende)

Características de un Programa

  • Está escrito en un lenguaje de programación específico
  • Puede ser compilado o interpretado
  • Se ejecuta en una computadora
  • Puede ser ejecutado múltiples veces
  • Puede ser modificado y mejorado

Ejemplo: Programa vs Algoritmo

📝 Algoritmo (en español)
  1. Recibir dos números
  2. Sumarlos
  3. Mostrar el resultado
💻 Programa (en PSeInt)
Algoritmo Suma
  Definir a, b, c Como Entero
  Leer a
  Leer b
  c <- a + b
  Escribir c
FinAlgoritmo

Ciclo de Vida de un Programa

  1. Análisis: Entender el problema a resolver
  2. Diseño: Planear la solución (algoritmo)
  3. Codificación: Escribir el código
  4. Pruebas: Verificar que funciona correctamente
  5. Mantenimiento: Corregir errores y mejorar
🗣️

1.3 Lenguajes de Programación

Un lenguaje de programación es un conjunto de reglas y símbolos que se usan para escribir instrucciones que una computadora puede ejecutar.

Clasificación por Nivel

Nivel Características Ejemplos
Alto nivel Parecido al inglés, fácil de leer, portable Python, Java, JavaScript, PSeInt
Nivel medio Acceso a hardware pero con abstracciones C, C++, Rust
Bajo nivel Casi directo al hardware, difícil de leer Ensamblador, Código máquina

Elementos de un Lenguaje de Programación

  • Sintaxis: Reglas de cómo escribir el código (gramática)
  • Semántica: Significado de las instrucciones
  • Palabras reservadas: Palabras con significado especial (Si, Mientras, Definir...)
  • Identificadores: Nombres que le damos a las variables y funciones
  • Operadores: Símbolos que realizan operaciones (+, -, *, /, <-)

PSeInt como Lenguaje Educativo

¿Por qué PSeInt?
  • Sintaxis en español (más fácil de entender)
  • No requiere instalación compleja
  • Enfocado en la lógica, no en la syntax
  • Permite pasar fácilmente a lenguajes reales

1.5 Paradigmas de Programación

Un paradigma es una forma o estilo de programar. Define cómo organizamos y estructuramos nuestro código.

Paradigma Imperativo (Procedural)

Enfoque: Secuencia de instrucciones

El programa es una serie de pasos que se ejecutan en orden. Se modifican las variables directamente.

Ejemplos: C, Pascal, BASIC, PSeInt (básico)

ejemplo_imperativo.pse 
Algoritmo SumaImperativa
  Definir suma, i Como Entero
  suma <- 0
  Para i <- 1 Hasta 10 Hacer
    suma <- suma + i
  FinPara
  Escribir suma
FinAlgoritmo

Paradigma Orientado a Objetos (POO)

Enfoque: Objetos y clases

El programa se organiza en objetos que tienen atributos (datos) y métodos (funciones).

Ejemplos: Java, C#, Python, C++

Conceptos clave:
  • Clase: Plantilla para crear objetos (ej: "Perro")
  • Objeto: Instancia de una clase (ej: "Fido")
  • Atributo: Propiedad del objeto (ej: nombre, color)
  • Método: Acción del objeto (ej: ladr, correr)
  • Herencia: Clases que heredan de otras

Paradigma Funcional

Enfoque: Funciones puras, sin efectos secundarios

Se evita cambiar el estado de las variables. Todo se hace mediante transformaciones de datos.

Ejemplos: Haskell, Lisp, Erlang, JavaScript (funcional)

Comparación de Paradigmas

Paradigma Enfoque Ventaja Desventaja
Imperativo Pasos a seguir Fácil de entender para principiantes Puede ser desordenado en programas grandes
POO Objetos interactuando Organizado, reutilizable Curva de aprendizaje mayor
Funcional Transformación de datos Código más predecible Difícil para algunos problemas

1.6 Compiladores e Intérpretes

Los lenguajes de programación necesitan ser traducidos a código máquina para que la computadora los entienda. Hay dos formas de hacerlo:

🔧 Compilador

Traduce todo el programa de una vez antes de ejecutarlo.

  • Crea un archivo ejecutable (.exe)
  • Errores mostrados después de compilar
  • Programa resultante es rápido
  • Ejemplos: C, C++, Rust, Go
🔄 Intérprete

Traduce y ejecuta línea por línea mientras corre.

  • No crea archivo ejecutable
  • Errores mostrados en tiempo real
  • Programa resultante es más lento
  • Ejemplos: Python, JavaScript, PSeInt

Comparación Detallada

Característica Compilador Intérprete
Velocidad de ejecución ✅ Rápido ⚠️ Más lento
Velocidad de desarrollo ⚠️ Más lento ✅ Más rápido
Detección de errores Al compilar todo En tiempo real
Portabilidad ⚠️ Depende del sistema ✅ Más portable
Uso de memoria Menos en tiempo de ejecución Más en tiempo de ejecución

¿Y PSeInt?

PSeInt es un intérprete

PSeInt interpreta el código línea por línea. Por eso puedes ver los errores inmediatamente y el programa se ejecuta directamente sin necesidad de compilar.

Proceso en PSeInt:

  1. Escribes el código en pseudocódigo
  2. PSeInt lo interpreta línea por línea
  3. Si hay errores, los muestra inmediatamente
  4. Si no hay errores, ejecuta el programa

2.1 Análisis de Problemas

Antes de programar, es fundamental entender completamente el problema que queremos resolver. El análisis de problemas es el primer paso en la resolución de problemas.

Pasos del Análisis de Problemas

  1. Identificar el problema: ¿Qué se quiere resolver exactamente?
  2. Recopilar información: ¿Qué datos tenemos? ¿Qué necesitamos?
  3. Definir entradas y salidas: ¿Qué datos de entrada hay? ¿Qué resultado esperamos?
  4. Identificar restricciones: ¿Qué limitaciones hay?
  5. Desarrollar una solución: Crear el algoritmo

Ejemplo: Calcular el Promedio de un Grupo

Paso 1: Identificar el problema

Calcular el promedio de las calificaciones de un grupo de estudiantes.

Paso 2: Recopilar información
  • Número de estudiantes (n)
  • Calificación de cada estudiante
Paso 3: Definir entradas y salidas
  • Entrada: Las calificaciones (n números)
  • Salida: El promedio (un número real)
Paso 4: Restricciones
  • Las calificaciones deben estar entre 0 y 100
  • El número de estudiantes debe ser mayor a 0
Paso 5: Solución

Fórmula: promedio = suma de calificaciones / número de estudiantes

Herramientas de Análisis

  • Diagrama de flujo: Representación gráfica del algoritmo
  • Pseudocódigo: Representación en lenguaje natural
  • Tablas de verdad: Para analizar condiciones lógicas
  • Prueba de escritorio: Simular la ejecución manualmente
📊

2.2 Representación de Algoritmos

Los algoritmos se pueden representar de diferentes maneras para facilitar su comprensión y comunicación.

A. Diagrama de Flujo (Gráfica)

Representación visual de un algoritmo usando figuras geométricas.

Figuras y su significado:
Figura Nombre Significado
⬭ (Óvalo) Terminal Inicio o fin del algoritmo
▭ (Rectángulo) Proceso Operación o asignación
◇ (Rombo) Decisión Condición (Sí/No)
▱ (Paralelogramo) Entrada/Salida Leer datos o mostrar resultados
↓ (Flecha) Conector Dirección del flujo
Ejemplo: Diagrama de Flujo - Sumar dos números
Inicio
Leer A, B
C ← A + B
Escribir C
Fin

B. Pseudocódigo

Representación textual del algoritmo usando lenguaje natural estructurado.

Reglas del Pseudocódigo
  • Usar indentación para mostrar estructura
  • Palabras clave en mayúsculas o destacadas
  • Ser claro y conciso
  • Usar nombres descriptivos
Ejemplo: Pseudocódigo - Par o Impar
par_impar.pse 
Algoritmo ParImpar
  Definir numero Como Entero
  Escribir "Ingrese un número:"
  Leer numero
  
  Si numero MOD 2 = 0 Entonces
    Escribir "El número es par"
  SiNo
    Escribir "El número es impar"
  FinSi
FinAlgoritmo

C. Comparación de Métodos

Método Ventajas Desventajas
Diagrama de Flujo Visual, fácil de entender Difícil para algoritmos complejos
Pseudocódigo Más detallado, fácil de convertir a código Menos visual

2.3 Diseño de Algoritmos Aplicados

El diseño de algoritmos es la habilidad de crear soluciones efectivas a problemas específicos. Veamos ejemplos prácticos.

Ejemplo 1: Calcular el factorial de un número

Problema

Calcular el factorial de un número N (N! = N × (N-1) × (N-2) × ... × 1)

factorial.pse 
Algoritmo Factorial
  Definir n, factorial, i Como Entero
  
  Escribir "Ingrese un número:"
  Leer n
  
  factorial <- 1
  Para i <- 1 Hasta n Hacer
    factorial <- factorial * i
  FinPara
  
  Escribir "El factorial es: ", factorial
FinAlgoritmo

Ejemplo 2: Encontrar el mayor de una lista

Problema

Dada una lista de N números, encontrar el mayor.

mayor_lista.pse 
Algoritmo MayorDeLista
  Definir n, num, mayor, i Como Entero
  
  Escribir "¿Cuántos números?"
  Leer n
  
  Escribir "Ingrese el primer número:"
  Leer mayor
  
  Para i <- 2 Hasta n Hacer
    Escribir "Ingrese el siguiente número:"
    Leer num
    Si num > mayor Entonces
      mayor <- num
    FinSi
  FinPara
  
  Escribir "El mayor es: ", mayor
FinAlgoritmo

Ejemplo 3: Verificar si un número es primo

Problema

Determinar si un número N es primo (solo divisible por 1 y por sí mismo).

numero_primo.pse 
Algoritmo NumeroPrimo
  Definir n, i, divisor Como Entero
  Definir esPrimo Como Lógico
  
  Escribir "Ingrese un número:"
  Leer n
  
  esPrimo <- VERDADERO
  divisor <- 2
  
  Mientras divisor < n Y esPrimo Hacer
    Si n MOD divisor = 0 Entonces
      esPrimo <- FALSO
    FinSi
    divisor <- divisor + 1
  FinMientras
  
  Si esPrimo Entonces
    Escribir "Es primo"
  SiNo
    Escribir "No es primo"
  FinSi
FinAlgoritmo

Consejos para Diseñar Algoritmos

✅ Hacer
  • Dividir problemas grandes en pequeños
  • Usar nombres descriptivos
  • Comentar el código
  • Probar con diferentes valores
❌ Evitar
  • Código duplicado
  • Nombres confusos (a, b, x)
  • Ciclos infinitos
  • No validar entradas

5.1 Arreglos Unidimensionales

Un arreglo unidimensional es una estructura de datos que almacena una colección de elementos del mismo tipo en posiciones contiguas de memoria.

Analogía

Un arreglo es como una fila de casilleros, donde cada casillero tiene un número (índice) y guarda un valor.

5.1.1 Declaración

La declaración indica al compilador que necesitamos un arreglo, especificando:

  • Nombre del arreglo
  • Tipo de datos que almacenará
  • Tamaño (cantidad de elementos)
declaracion.pse 
Algoritmo DeclaracionArreglo
  // Declarar un arreglo de 5 enteros
  Definir numeros Como Entero[5]
  
  // Declarar un arreglo de 10 caracteres
  Definir letras Como Caracter[10]
  
  // Declarar un arreglo de 8 reales
  Definir precios Como Real[8]
FinAlgoritmo
💡 ¿Cómo se guarda en memoria?

Cuando declaras numeros[5], el sistema reserva 5 posiciones contiguas en memoria RAM. Si cada Entero ocupa 2 bytes, se reservan 10 bytes consecutivos.

5.1.2 Inicialización

La inicialización asigna valores iniciales a los elementos del arreglo.

inicializacion.pse 
Algoritmo InicializacionArreglo
  Definir edades Como Entero[5]
  
  // Inicialización elemento por elemento
  edades[1] <- 18
  edades[2] <- 22
  edades[3] <- 19
  edades[4] <- 21
  edades[5] <- 20
  
  // O inicialización directa (varía según lenguaje)
  // edades <- [18, 22, 19, 21, 20]
FinAlgoritmo
💡 Índices

En PSeInt, los índices comienzan en 1. En muchos lenguajes (Java, C, Python) comienzan en 0. Es importante conocer la convención del lenguaje que uses.

5.1.3 Operaciones

📖 Lectura

Acceder al valor de una posición:

valor <- edades[3]

Obtiene el valor en la posición 3

✏️ Escritura

Asignar un valor a una posición:

edades[3] <- 25

Cambia el valor en la posición 3

🔍 Búsqueda

Encontrar un valor en el arreglo:

Para i <- 1 Hasta 5 Hacer
  Si edades[i] = 22 Entonces
    Escribir "Encontrado en: ", i
  FinSi
FinPara
🔄 Reemplazo

Cambiar un valor por otro:

Para i <- 1 Hasta 5 Hacer
  Si edades[i] = 18 Entonces
    edades[i] <- 19
  FinSi
FinPara
operaciones_arreglo.pse 
Algoritmo OperacionesArreglo
  Definir nums Como Entero[5]
  Definir i, busqueda, encontrado Como Entero
  
  // Inicializar
  Para i <- 1 Hasta 5
    nums[i] <- i * 10
  FinPara
  
  // Lectura
  Escribir "Valor en posición 3: ", nums[3]
  
  // Escritura
  nums[3] <- 999
  Escribir "Nuevo valor en 3: ", nums[3]
  
  // Búsqueda
  busqueda <- 30
  encontrado <- 0
  Para i <- 1 Hasta 5
    Si nums[i] = busqueda Entonces
      encontrado <- i
    FinSi
  FinPara
  Escribir "El valor ", busqueda, " está en: ", encontrado
FinAlgoritmo

5.2 Arreglos Multidimensionales

Un arreglo multidimensional es un arreglo que contiene otros arreglos, formando una estructura de filas y columnas (matriz).

Analogía

Una matriz es como una cuadrícula o tabla, donde cada celda tiene una fila y una columna (como una hoja de cálculo de Excel).

5.2.1 Declaración

Para declarar una matriz, se especifican dos dimensiones: filas y columnas.

declaracion_matriz.pse 
Algoritmo DeclaracionMatriz
  // Matriz de 3 filas y 4 columnas
  Definir notas Como Entero[3, 4]
  
  // Matriz de 5x5 para un juego
  Definir tablero Como Caracter[5, 5]
  
  // Matriz de 2x3 para decimales
  Definir promedios Como Real[2, 3]
FinAlgoritmo

5.2.2 Inicialización

inicializacion_matriz.pse 
Algoritmo InicializacionMatriz
  Definir matriz Como Entero[2, 3]
  
  // Inicialización por filas y columnas
  matriz[1, 1] <- 10
  matriz[1, 2] <- 20
  matriz[1, 3] <- 30
  matriz[2, 1] <- 40
  matriz[2, 2] <- 50
  matriz[2, 3] <- 60
  
  // O con ciclos anidados
  Definir i, j Como Entero
  Para i <- 1 Hasta 2
    Para j <- 1 Hasta 3
      matriz[i, j] <- (i-1)*3 + j
    FinPara
  FinPara
FinAlgoritmo

5.2.3 Operaciones

📖 Lectura
valor <- matriz[2, 3]

Obtiene el valor en fila 2, columna 3

✏️ Escritura
matriz[2, 3] <- 99

Asigna 99 a la posición [2,3]

🔍 Búsqueda
Para i <- 1 Hasta 2
  Para j <- 1 Hasta 3
    Si matriz[i,j] = 50 Entonces
      Escribir "Encontrado en [", i, ",", j, "]"
    FinSi
  FinPara
FinPara
🔄 Reemplazo
Para i <- 1 Hasta 2
  Para j <- 1 Hasta 3
    Si matriz[i,j] > 40 Entonces
      matriz[i,j] <- 0
    FinSi
  FinPara
FinPara
💡 Almacenamiento en Memoria

Aunque la matriz se ve como una cuadrícula, en memoria RAM se guarda de forma lineal. Por defecto, se almacena por filas: primero la fila 1 completa, luego la fila 2, etc.

matriz[2,3] → En memoria está en la posición: (fila-1)*columnas + columna

5.2.4 Aplicaciones

📝 Ejemplos prácticos
  • Tablas de calificaciones (alumnos x materias)
  • Tableros de juegos (ajedrez, gato, buscaminas)
  • Mapas y laberintos
  • Datos de sensores (tiempo x ubicación)
  • Imágenes (píxeles en fila x columna)
  • Hojas de cálculo (Excel)
⚡ Operaciones comunes
  • Recorrer toda la matriz (ciclos anidados)
  • Sumar filas o columnas
  • Encontrar el mayor/menor
  • Transponer (intercambiar filas por columnas)
  • Buscar un elemento específico
ejemplo_matriz.pse 
Algoritmo SumarFilas
  Definir matriz Como Entero[3, 4]
  Definir i, j, suma Como Entero
  
  // Llenar matriz
  Para i <- 1 Hasta 3
    Para j <- 1 Hasta 4
      matriz[i, j] <- i * j
    FinPara
  FinPara
  
  // Sumar cada fila
  Para i <- 1 Hasta 3
    suma <- 0
    Para j <- 1 Hasta 4
      suma <- suma + matriz[i, j]
    FinPara
    Escribir "Suma fila ", i, ": ", suma
  FinPara
FinAlgoritmo

Condiciones y Operadores Lógicos

Las condiciones permiten comparar valores y tomar decisiones. Los operadores lógicos combinan múltiples condiciones.

🔍 Operadores de Comparación

=
Igual a

<>
Diferente de
5 <> 3 → Verdadero
>
Mayor que
7 > 3 → Verdadero
<
Menor que
3 < 7 → Verdadero
>=
Mayor o igual
5 >= 5 → Verdadero
<=
Menor o igual
3 <= 5 → Verdadero

🧠 Operadores Lógicos

Combinan dos o más condiciones:

Y (AND)
Verdadero SOLO si AMBAS condiciones son verdaderas
V Y V= V
V Y F= F
F Y V= F
F Y F= F
O (OR)
Verdadero si AL MENOS UNA condición es verdadera
V O V= V
V O F= V
F O V= V
F O F= F
NO (NOT)
Invierte el valor de la condición
NO V= F
NO F= V

Algoritmo ejemplo_condiciones_logicas
  Definir edad, saldo Como Entero
  Definir tienePermiso Como Logico
  
  edad <- 25
  saldo <- 100
  tienePermiso <- Verdadero
  
  // Operador Y (AND)
  Si edad >= 18 Y tienePermiso Entonces
    Escribir "Puede entrar"
  FinSi
  
  // Operador O (OR)
  Si saldo > 50 O tienePermiso Entonces
    Escribir "Acceso permitido"
  FinSi
  
  // Operador NO (NOT)
  Si NO tienePermiso Entonces
    Escribir "Acceso denegado"
  FinSi
FinAlgoritmo

💡 Conceptos Clave de las Funciones
  • Nombre: Identifica a la función (ej: Sumar)
  • Parámetros: Datos que recibe (ej: x, y)
  • Cuerpo: Código que ejecuta
  • Retorno: El valor que devuelve (FinFuncion <- valor)

Funcion area <- CalcularArea(base, altura)
  Definir area Como Real
  area <- base * altura
  FinFuncion <- area
